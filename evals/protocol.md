# Evaluation protocol draft

1. Create a pilot of 20 base scenes and 30–50 questions. Record generation, independent raster verification, failure reasons and model access. Use pilot results to select legible supported layouts before freezing other groups.
2. Freeze the accepted set and hash files and task selection. Stratify the evaluation by skill, difficulty and group. Keep all siblings together and keep pilot groups out of frozen evaluation.
3. Use matched text-only, full-image and verified-readings conditions where applicable. Report semantic sensitivity, nuisance invariance and worst-case accuracy across variants. Include subgroup sizes and group-based intervals when sample sizes support them.
4. Count attempted, completed, valid and correct outputs and record provider errors and parse failures. Report valid-only and all-attempt denominators, observed cost and latency, and genuine failure examples. Label fixture outputs DEMO ONLY.

Before a measured run, record authorizing account, provider/model revision, exact selection hash, conditions, caps and run command. This draft describes a proposed experiment.
